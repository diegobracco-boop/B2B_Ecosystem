Manual técnico · B2B Ecosystem · FY27 (Abr-2026 → Mar-2027)
Ecosistema B2B & WLs
Un set de herramientas de autoservicio para que Planning y Finanzas B2B analicen performance, varianzas y pace — sin depender de extracciones manuales. Este manual documenta la arquitectura, los flujos de datos y los procedimientos de cada pieza.
🎯 Qué preguntas responde
¿Cómo venimos vs Budget / Forecast / Run Rate?Por país, producto y canal, mes a mes, B2B y B2B2C. → P&L Accounting, Hub
¿La varianza es de precio o de volumen?Descomposición PxQ del delta baseline vs goal por segmento. → P&L Accounting, Hub
¿Cómo se arma el Net Revenue / FVM, línea por línea?NR Bridge y waterfall entre dos escenarios. → P&L Managerial, Hub
¿Cuál es el pace diario?D-1, MTD, vs Budget del mes, vs LY. Todas las mañanas 08:00. → Daily Dashboard
¿Cierra igual el P&L contable y el gestional?La misma performance como líneas de P&L (contable) y como FVM (managerial). → P&L Accounting vs P&L Managerial

Guía del equipo
Glosario
Los términos que aparecen en las landings y en el resto del manual.
💰 Métricas de P&L
GB · Gross BookingsVolumen bruto transaccionado.
NR · Net RevenueIngreso neto (GB menos descuentos, incentivos, impuestos de revenue, cancelaciones, etc.).
OC · Operating ContributionNR + Cost of Revenue + Sales & Marketing (los costos entran con signo negativo). Es la línea principal del P&L contable.
FVMFinancial Value Margin — la métrica de la vista gestional/managerial (en el código figura como npv).
Revenue marginNR / GB, en %.
📊 Las dos vistas del P&L
ContableEl P&L con las líneas estándar de accounting (Operating Contribution). Lo usa Finanzas / Planning. Landing: P&L Accounting. Pipeline de datos: Inputs_Planning_PnL.
Gestional (managerial)La misma performance vista como FVM, con waterfall de palancas y NR Bridge. Lo usa Planning / Gerencia. Landing: P&L Managerial. Pipeline propio: actuals_gestional_upload.py.
Son la misma realidad de negocio contada de dos formas — no dos fuentes que se contradicen. Los pipelines son independientes a propósito.
🧭 Escenarios (Baseline y Goal)
BaselineLa "foto realista": actuals de los meses cerrados + la mejor proyección disponible para los abiertos (run rate → forecast → budget según el mes). Es contra lo que se compara.
GoalEl objetivo elegido para comparar: se selecciona en la landing entre Budget, Forecast o Last Year.
BudgetEl presupuesto oficial FY27 (12 meses), fijo.
ForecastLa última proyección revisada. Contable: sale de CSV Hyperion. Gestional: sale de los Modelos Forecast en Excel.
Run RateProyección de corto plazo basada en el pace reciente.
Last Run Rate · LRREl run rate del corte anterior (para ver cómo se movió la proyección).
Last Year · LYEl FY anterior completo (FY26: Abr-2025 → Mar-2026), real.
🏷️ Segmentos
B2B2C / WLsWhite Labels — partners que venden con su marca sobre la plataforma de Despegar.
B2BVenta a otras empresas. Se abre en MAY (mayoristas) y MIN (minoristas).
GD · Gross DemandBase "directa" — fecha de transacción.
RI · Recibido IndirectoBase sobre fecha de check-in / reconocimiento. Solo aplica a B2B-MAY, que tiene doble base (GD y RI).
🔬 Técnicas de análisis
WaterfallGráfico de puente: descompone la diferencia entre dos números (ej. Baseline vs Goal) en sus componentes, barra por barra.
PxQ / PxQxMDescompone el delta de OC/GB en Precio (margen), Cantidad (volumen) y, en PxQxM, Mix e Interacción — por LOB, canal, país y producto.
NR BridgeAgrupa las ~27 líneas N2 del Net Revenue en 5-6 grupos legibles y muestra el puente entre escenarios.
Countries YoYCards por país con GB/NR/OC y variación año contra año (H1 / H2 / FY), con benchmark de Budget.
⚙️ Términos técnicos
Año fiscal / FY27Despegar cierra en marzo. FY27 = Abril 2026 a Marzo 2027.
PlanaTabla "larga" homologada (una fila por combinación de dimensiones + mes + monto) que arma el pipeline contable antes de construir los JSON.
HomologaciónMapear los códigos crudos del datalake / Excel a las dimensiones estándar (país, producto, línea de P&L) usando el Glosario.
JSON canónicoEl archivo de datos "fuente de verdad" por escenario que publica Inputs_Planning_PnL en Drive. Todas las landings contables deberían leer de acá.
CuboUn JSON con estructura data[lob][país][escenario][línea][mes] que arma plana_to_cube.py a partir de los canónicos, para la vista contable oculta.
@HEAD vs deployment publicadoclasp push sube a @HEAD (la URL /dev, para probar). La URL /exec que usa el negocio queda congelada hasta hacer clasp deploy -i <id>. Saltear ese paso = "publiqué" pero nadie ve el cambio.
claspCLI de Google para sincronizar código local ↔ Apps Script.
ToqanIA interna de Despegar. Hasta mediados de 2026 armaba las planas; se reemplazó por el pipeline local Inputs_Planning_PnL.

Recetas por tarea
Qué correr según lo que pasó. El detalle fino de cada script está en la Referencia operativa del módulo.
📅 Cerró un mes (llegaron los actuals)
Contable (P&L Accounting)Desde Inputs_Planning_PnL: run_all.bat → python baseline_builder.py → python plana_to_cube.py --upload. Recargar la landing (Ctrl+Shift+R). Sin deploy.
Gestional (P&L Managerial)Desde P&L_Managerial, con VPN: python actuals_gestional_upload.py. Un solo run.
DailySe incorpora solo en el run automático de las 08:00.
📈 Salió una ronda nueva de Forecast (Modelos XLSX)
GestionalActualizar FC_XLSX_DIR en actuals_gestional_upload.py a la carpeta semanal nueva → correr el script (con VPN).
ContableEl forecast contable NO sale de esos XLSX (sale de CSV Hyperion). Se actualiza upstream en Inputs_Planning_PnL al reprocesar.
Preview de un WIP sin publicarpython projections_gestional_builder.py --wip-folder "<ruta>" (gestional) / projections_validation_builder.py (contable). Muestra el borrador en la vista "Projection Review".
🎨 Hay que cambiar algo del dashboard (visual o lógica)
1
Editar el archivo local
Los .js / .html están en la carpeta del módulo. Commitear a git primero.
2
Publicar
clasp push (o --force) + clasp deploy -i <deploymentId>. El segundo paso NO es opcional — ver "Comandos frecuentes" para el ID de cada landing.
3
Verificar en la URL /exec
No en /dev. Recargar y confirmar que el cambio se ve.
🔎 Un número se ve mal
¿Contable vs gestional?Una diferencia chica entre P&L Accounting y Managerial es esperable. Grande = avisar.
¿Está viejo el dato?Revisar cuándo se corrió el pipeline (las landings muestran "Actualizado: …"). Si el mes cerró y no está, falta correr la receta "Cerró un mes".
¿Cambió pero no se ve?Casi siempre es cache del navegador (Ctrl+Shift+R) o que faltó el clasp deploy -i tras el push.
¿Falta un mes entero / da cero un escenario?Puede ser config desalineada (RUNRATE_MONTHS / FORECAST_MONTHS en config.py). Ver la Referencia operativa de Inputs Planning P&L.
🔌 Los scripts que consultan el Datalake (actuals_gestional_upload.py, daily_sync.py) necesitan VPN. Un error de conexión / SSL casi siempre es eso, no un bug del código.

🔄 Cuándo re-ejecutar Python
1
Datos de P&L Accounting (contable)
Cuando cambian los CSV Hyperion o llega el actuals de un mes cerrado → desde Inputs_Planning_PnL: run_all.bat (regenera los 6 JSON canónicos) + python baseline_builder.py + python plana_to_cube.py --upload. La vista visible (EPM) lee los canónicos directo.
2
Datos de P&L Managerial (gestional)
Cuando cambian los Modelos Forecast XLSX o llega un mes de actuals → desde P&L_Managerial: python actuals_gestional_upload.py (un solo run cubre actuals ODBC + forecast XLSX; requiere VPN). Actualizar antes FC_XLSX_DIR en el script si hay un corte semanal nuevo.
3
Datos del Daily Dashboard
Corre solo (Task Scheduler 08:00). Manual: desde Daily_Dashboard: python daily_sync.py (requiere VPN).
4
Al cambiar código Apps Script
Modificar los .js o .html y correr clasp push + clasp deploy -i <deploymentId> (ver "Comandos frecuentes").
⚡ Deploy (clasp)
1
Editar código localmente
Modificar .js, .html en la carpeta del proyecto en VS Code u otro editor
2
Push a Apps Script
Desde la terminal, dentro de la carpeta del proyecto:
clasp push --force
3
Redeployar a producción (obligatorio)
⚠️ clasp push solo actualiza el deployment @HEAD (la URL /dev, para probar). La URL /exec que usa el negocio queda congelada hasta correr clasp deploy -i <deploymentId> -d "desc" con el ID de esa landing (ver tabla en "Comandos frecuentes"). Recién ahí, recargar la URL /exec para confirmar.
